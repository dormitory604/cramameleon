# Domain Docs

本项目采用 single-context 领域文档布局：根目录 `GLOSSARY.md` 保存领域术语，`docs/adr/` 保存架构决策记录。

## 阅读顺序

探索代码或讨论设计前：

1. 阅读 `项目架构与模块契约.md`，以其为当前开发约定。
2. 如果根目录 `GLOSSARY.md` 存在，阅读其中与本次工作相关的术语定义。
3. 如果 `docs/adr/` 存在，阅读涉及本次改动领域的 ADR。

术语表或 ADR 尚不存在时，直接继续工作；由 `/domain-modeling` 在澄清实际术语或形成实际决策时按需创建。

## 使用约定

- 任务、规格、实现和评审使用术语表中的规范名称。
- 新术语或多义词需要澄清时，交由 `/domain-modeling` 处理；术语表只保存领域定义。
- 新方案与现有 ADR 冲突时，明确指出对应 ADR、冲突内容及权衡理由。
- 调整领域文档时，保持与 `项目架构与模块契约.md` 中的职责和契约一致；发现冲突时明确指出。
