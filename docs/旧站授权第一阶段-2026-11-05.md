# 旧站授权第一阶段

本文保留第一阶段的历史状态；源码缺口已补齐，后续实现与验证见 [旧站身份与课程资料接入](旧站身份与资料接入-2026-11-05.md)。

日期：2026-11-05。范围为 Cramameleon 的授权客户端、真实用户会话和入口状态。本阶段没有替换旧站运行文件，没有更改旧站六月源码目录，没有登录真实用户或消耗下载/模型额度。

## 已实现

- `APP_ENV=old-site`：配置固定新旧站 origin、客户端认证、明确用户允许名单和独立 AES-256-GCM 凭据密钥；继续只监听 loopback，公网由 HTTPS 反代接入。
- `GET /api/auth/config` 返回进入方式。旧站模式无会话时不显示口令框或学习界面，只提供返回旧站的入口；配置获取失败时保持关闭。
- start 产生 state、浏览器绑定 Cookie 和 S256 verifier，流程 5 分钟且有数量上限。数据库只保存 state/Cookie 哈希，verifier 加密。
- callback 原子消费匹配浏览器的流程，再向固定旧站 token 接口兑换 code。核验 issuer、subject、scope、有效期和允许名单，产生独立应用会话。
- 用户按 issuer + subject 唯一映射，展示名称不能改变用户归属。原统一内部身份不自动迁移给任何旧站用户。
- 独立应用 Cookie 使用 HttpOnly、host-only，HTTPS 下 Secure；跨站流程使用 SameSite=Lax。旧站模式的内部口令路由不存在，旧内部会话不能进入。
- 上游受限凭据按应用会话加密绑定。换账号/重新授权撤销旧会话及旧凭据，退出删除凭据并尝试向旧站撤销；上游暂不可用时本地会话撤销仍有效。
- 浏览器业务 POST 校验固定 Origin 和当前用户 `X-Cram-User`。过期或已换身份的标签页无法把原用户资料提交给新用户模型请求，或退出新用户的会话。
- 标签页间通知账号切换/退出；清空原用户界面，取消旧模型与导入任务，缓存仍按用户隔离。资料凭据期限不等于应用会话期限。

本阶段实现的是授权客户端。真实旧站签发 code、兑换 token、资料搜索/目录、条目授权与字节读取接口尚未接通；健康中的 oldSite 字段表示配置的运行模式，不代表已探测到完整旧站链路。

## 冻结的旧站授权接口约定

新后端 start 跳转旧站 `/integrations/cramameleon/authorize`，参数为 response_type=code、client_id、redirect_uri、state、code_challenge、code_challenge_method=S256、scope=`entry materials:read` 和可选资源 context JSON。

旧站授权页应继续使用旧站 localStorage 中的 JWT 调用自身 POST authorize。未登录时只通过旧站内部续接地址完成登录，不能把任意外部 redirect 当作合法回调。code 建议 60 秒、单次使用，绑定用户、客户端、完整回调、scope 与 challenge。

新后端调用固定的 `POST /api/integrations/cramameleon/token`，使用 HTTP Basic 客户端认证和 application/x-www-form-urlencoded 请求体：

```text
grant_type=authorization_code
client_id=cramameleon
code=<短时单次授权码>
redirect_uri=<配置的新站 origin>/api/auth/old-site/callback
code_verifier=<本流程 verifier>
```

成功响应：

```json
{
  "issuer": "https://旧站域名",
  "subject": "123",
  "name": "昵称",
  "access_token": "独立受限随机凭据，至少32字符",
  "expires_in": 28800,
  "scope": "entry materials:read"
}
```

issuer 必须等于配置 OLD_SITE_URL，subject 为正整数的规范字符串，expires_in 不大于 8 小时。访问凭据不是旧站 JWT，不应被普通账号接口接受。

撤销使用相同客户端认证，调用 `POST /api/integrations/cramameleon/revoke`，请求体 `token=<受限凭据>`。回调失败只向应用根页面传固定错误码，随后前端清理地址栏；不把上游错误正文或秘密暴露给用户。

`.env.old-site.example` 仅是模板，没有真实域名、准入用户或密钥。部署须先完成旧站对应能力，再配置旧站入口 `/cramameleon` 和受保护回调；当前运行的 internal 服务保持原状。
