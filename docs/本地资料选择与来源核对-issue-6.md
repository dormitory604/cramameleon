## 必须保留的 B 阻塞

### B-1：旧题板来源通过历史重新进入取消勾选后的请求

实际浏览器步骤：导入两份资料 → 根据第一份搜索并生成带来源的题板 → 取消勾选第一份 → 仅依据第二份发送新问题。捕获的新请求中，当前资料元数据只包含第二份，但 assistant 历史的 `题目记录` 仍包含第一份 `quiz.sources[].text`，包括独立标记 `SOURCE_SCOPE_LEAK_6`。

归属：B 的 `src/agent/context.ts:buildHistory` 将完整 Quiz JSON 序列化到历史，Adapter 和请求投影继续发送。移除资料也不能删除已经存在的题板历史。普通回答若已经转述旧资料，也需要 B 明确历史来源和提交范围的策略；不能在 A 删除用户可见记录或用 Prompt 声明隔离来掩盖实际请求。

回归：`tests/e2e/issue6.materials.spec.ts` 中 `BLOCKED B` 用例先作为普通测试运行，确实在“下一轮请求不得含旧资料标记”断言失败，之后在该断言前加明确 `test.fail` 及 B 归属。它持续执行真实复现，不是 skip；修复后成为 unexpected pass，提示移除阻塞标记。

**受影响验收：未选内容不进入本轮模型请求、跨轮资料范围隔离未通过。** 首轮选择范围和当轮未读取引用的校验通过，不能抵消此阻塞。

### B-2：检索截断／预算耗尽缺少可观察状态

当前每次检索最多 6,000 字、每轮最多 8,000 字。六个 1,800 字块的同一查询，先后结果长度为 `[1800,1800,1800,600]`、`[1800,200]`、`[]`。实际 Adapter 的工具结果在预算耗尽后与新轮次确无匹配时均为 `{untrustedMaterial:true,chunks:[]}`，没有截断、覆盖范围或预算状态，无法准确区分原因。

归属：B 的检索工具、结果与必要公共契约。A 可以展示已有解析警告和已发布引用片段，但不能凭空推断检索覆盖范围。公开 Adapter 回归保留为执行中的 TODO。

**受影响验收：检索片段被截断／耗尽时，教学表述能够确定真实可用范围的场景仍阻塞。** PDF 部分页缺文字的解析警告是另一条路径，已有当前通过证据。

### B-3：重复检索把此前较长已读引用覆盖为短片段

同一组数据第二次检索后，`resolve(c1)` 从此前已读的 1,800 字变为 200 字。原因是 `ContextSources` 按键用最后一次短片段覆盖之前记录。没有接受未读内容，但丢失了本轮已经读到的引用支持。

归属：B 的 `src/tools/contextSources.ts`。公开模块回归要求保留此前已读的 1,800 字，当前以 TODO 明确记录实际 200 字的失败。

**受影响验收：反复读取／预算受限后的完整来源依据保留仍阻塞。** 来源窗口能忠实展示发布的片段与本机缓存，但不能修复运行时读证据集合。
